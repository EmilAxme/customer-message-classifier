# Customer Message Classifier

Небольшой production-ready сервис, который через **OpenAI-совместимый API**
классифицирует обращения клиентов и извлекает из них структурированные данные.

Для каждого обращения сервис определяет:

- **тип**: `order` | `complaint` | `question`;
- **товар** (`product`);
- **контакты**: `phone` и `email`.

Результат возвращается в виде JSON и валидируется через Pydantic.

Использовать можно двумя способами:

- **Веб-приложение** (для пользователей без знания кода) — наглядный интерфейс:
  вставил/загрузил обращения → кнопка → таблица → скачать Excel/CSV/JSON.
  См. [`ИНСТРУКЦИЯ.md`](ИНСТРУКЦИЯ.md). Запуск: двойной клик по
  `Запустить.command` или `streamlit run app.py`.
- **CLI** — пакетная обработка `input.json` → `output.json` (`python main.py`).

## Стек

- Python 3.11+
- [`openai`](https://pypi.org/project/openai/) — официальный SDK (работает с любым
  OpenAI-совместимым endpoint через `base_url`)
- Pydantic v2 — модели и валидация
- Tenacity — повторные попытки с экспоненциальной задержкой
- python-dotenv — загрузка переменных окружения
- `logging` — логирование

## Установка и запуск

```bash
pip install -r requirements.txt
cp .env.example .env        # затем впишите свой ключ и endpoint
python main.py
```

После запуска результат записывается в `output.json`.

## Переменные окружения

| Переменная                 | Назначение                                   | По умолчанию                |
| -------------------------- | -------------------------------------------- | --------------------------- |
| `OPENAI_API_KEY`           | API-ключ (обязательно)                       | —                           |
| `OPENAI_BASE_URL`          | Базовый URL endpoint'а                       | `https://codex.sale/v1`     |
| `OPENAI_MODEL`             | Используемая модель                          | `gpt-5.4-mini`              |
| `REQUEST_INTERVAL_SECONDS` | Пауза между запросами (сек); 0 = без пауз    | `0`                         |

> Клиент совместим с любым OpenAI-подобным провайдером — достаточно поменять
> `OPENAI_BASE_URL`, `OPENAI_API_KEY` и `OPENAI_MODEL` (официальный OpenAI,
> OpenRouter, локальный сервер и т.д.).

## Как это работает

1. `main.py` читает `input.json` и валидирует каждую запись в `CustomerMessage`.
2. Для каждого обращения `ClassifierClient.classify` вызывает `chat.completions`
   с `temperature=0` и системным промптом, который задаёт категории, правила
   извлечения и точную форму JSON-ответа.
3. Ответ парсится (`json.loads`, с допуском на ```-обёртку) и валидируется
   (`Extraction.model_validate`) — гарантия корректной структуры.
4. `id` добавляется к результату на стороне сервиса, а не запрашивается у модели.

## Обработка ошибок

Повторные попытки реализованы через **Tenacity**: до 4 попыток с экспоненциальной
задержкой. Повторяются только транзиентные ошибки:

- таймауты (`APITimeoutError`), сетевые ошибки (`APIConnectionError`);
- rate limit (`RateLimitError`);
- ошибки сервера 5xx (`InternalServerError` / `APIStatusError >= 500`);
- ошибки парсинга JSON и валидации Pydantic (`LLMResponseError`).

Постоянные ошибки (некорректный запрос, неверный ключ) не повторяются. Если
обработка обращения окончательно не удалась, в результат попадает запись вида:

```json
{ "id": 5, "error": "API request failed" }
```

Встроенные ретраи SDK отключены (`max_retries=0`) — единственный слой повторов
это Tenacity.
